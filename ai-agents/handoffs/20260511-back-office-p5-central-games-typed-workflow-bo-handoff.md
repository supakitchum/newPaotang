## Typed Create Workflow

The central games page now surfaces `Create game` as a typed documented operation that submits:

```text
POST /admin/central/games
```

Exposed create fields:

```text
code - required text field; lowercase letters, numbers, underscores, or hyphens
name - required text field
draw_at - required date-time field
close_at - optional date-time field
status - required select, constrained to draft or open; default draft
```

Create uses the existing admin API flow, including:

```text
X-Admin-Scope: central
Idempotency-Key generated by useAdminApi().idempotencyKey()
```

## Typed Update Workflow

The central games row/detail actions now include `Update` as a typed PATCH action that submits:

```text
PATCH /admin/central/games/{game_id}
```

Exposed update fields:

```text
code - optional text field
name - optional text field
draw_at - optional date-time field
close_at - optional date-time field
status - optional lifecycle transition select
```

The lifecycle transition field is intentionally blank by default and constrained to:

```text
open
reward_recorded
reward_checking
reward_verified
reward_published
```

QA should only select a status transition that is valid for the current backend state. Backend validation remains the source of truth:

```text
draft -> open
closed -> reward_recorded
reward_recorded -> reward_checking
reward_checking -> reward_verified
reward_verified -> reward_published
```

Close and archive are still dedicated actions and were not moved into the generic update transition field.

Update uses the existing admin API flow, including:

```text
X-Admin-Scope: central
Idempotency-Key generated by useAdminApi().idempotencyKey()
```
