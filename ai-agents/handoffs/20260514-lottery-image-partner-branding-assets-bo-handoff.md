## API Endpoints Used

Read current partner branding asset set:

```text
GET /api/v1/admin/central/partners/{partner_id}/lottery-branding-assets
X-Admin-Scope: central
```

Create central asset upload intent:

```text
POST /api/v1/admin/central/assets/uploads
X-Admin-Scope: central
Idempotency-Key: generated by useAdminApi()
```

Commit central asset:

```text
POST /api/v1/admin/central/assets/{asset_id}/commit
X-Admin-Scope: central
Idempotency-Key: generated by useAdminApi()
```

Save partner branding asset ids:

```text
PUT /api/v1/admin/central/partners/{partner_id}/lottery-branding-assets
X-Admin-Scope: central
Idempotency-Key: generated by useAdminApi()
```

## Payload Shape Used

The save payload uses the nested backend-preferred shape:

```json
{
  "version": "v1",
  "assets": {
    "logo_qr": { "asset_id": "ast_logo_qr" },
    "right_sidebar": { "asset_id": "ast_right_sidebar" },
    "logo_bottom": { "asset_id": "ast_logo_bottom" }
  }
}
```

The form uploads selected files through the central asset upload intent/commit flow first, then saves committed central asset ids.

For local/dev upload intents where the backend returns:

```text
storage_mode = local_dev_metadata_only
production_storage_ready = false
```

the UI skips direct external storage PUT and proceeds through the existing metadata-only commit behavior.

## UI Behavior

The form supports:

```text
logo_qr upload

logo_bottom upload
current asset preview when asset.url is available

asset metadata display for nested assets.logo_qr/assets.right_sidebar/assets.logo_bottom
generated image count
version field
status/lock display
file validation for PNG/WebP and max 5 MB

```

The form shows and preserves current backend asset metadata:

```text
asset_id
file_name
content_type
size_bytes
storage_path/storage_key
status
```

## Lock State Handling

When the backend response has:

```text
locked = true
status = locked
generated_image_count > 0
```

the UI:

```text
shows a warning with generated_image_count and lock_reason
disables version editing
disables file replacement inputs
disables upload actions
disables save
```

If the backend returns 403 or 409 during upload/save, the form surfaces a clear warning instead of relying only on client-side disabled state.
