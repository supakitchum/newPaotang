## Queue / Job Names

- `GenerateStockBatchChunkJob`
  - Queue: `stock-generation`
  - Processes one generation chunk in one DB transaction.
- `DispatchStockBatchImageJobs`
  - Queue: `stock-generation`
  - Releases existing `GenerateLotteryImageJob` jobs in chunks after stock generation completion.
- Existing image queue remains owned by `GenerateLotteryImageJob` through `lottery_images.queues.central`.

## Batch / Chunk State Model

- Large request creates a `stock_generation_batches` row with `status=queued`, `generated_count=0`, and no stock rows inserted during the request.
- Chunk jobs lock the chunk and batch rows with `lockForUpdate()`.
- A queued or failed chunk can enter `processing`; a completed chunk is skipped on retry.
- On successful insert, chunk becomes `completed` and batch progress increments by `round_count`.
- When `processed_rounds >= total_rounds`, the batch becomes `completed`, `completed_at` is set, `stock.generated` audit is written, and image dispatch begins.
- If the chunk transaction fails, inserted stock rows are rolled back and chunk/batch become `failed` with `failure_reason`.

## Sync vs Async Response Behavior

Synchronous example:

```http
POST /api/v1/admin/central/stock/generate
Idempotency-Key: stock-sync-1000

{
  "game_id": "gam_x",
  "total_count": 1000
}
```

Returns HTTP 202 with a completed generation batch.

Async example:

```http
POST /api/v1/admin/central/stock/generate
Idempotency-Key: stock-async-12000

{
  "game_id": "gam_x",
  "total_count": 12000
}
```

Returns HTTP 202 immediately with a queued batch:

```json
{
  "status": "queued",
  "requested_count": 12000,
  "generated_count": 0,
  "total_rounds": 12,
  "processed_rounds": 0,
  "chunk_rounds": 5
}
```

Batch progress APIs:

```http
GET /api/v1/admin/central/stock/generation-batches?game_id=gam_x&status=processing&limit=20
GET /api/v1/admin/central/stock/generation-batches/{batch_id}
```

Both require central admin scope and `stock.generate`.

## Idempotency Behavior

- Same actor + type + idempotency key + same normalized payload returns the original batch.
- Same actor + type + idempotency key + changed normalized payload returns HTTP 409 `idempotency_conflict`.
- The normalized generate payload stores quota inputs, seed/idempotency, total rounds, chunk rounds, and generation config only; it does not store generated numbers.

## Image Dispatch Separation Behavior

- Large async request dispatches `GenerateStockBatchChunkJob` only.
- It does not dispatch `GenerateLotteryImageJob` during the request.
- After final chunk completion, `DispatchStockBatchImageJobs` is dispatched.
- The dispatcher releases `GenerateLotteryImageJob` jobs in configured chunks using existing image queues.
