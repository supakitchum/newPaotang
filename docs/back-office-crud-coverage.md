Date: 2026-05-10

`DefaultRbacMenuSeeder.php`, `docs/permissions.md`, `docs/openapi.yaml`, and the
current `apps/back-office` route/catalog implementation.

This document intentionally does not calculate a final BO completion percentage.
Coordinator should calculate that from the counts and row-level evidence below.

## Counting Rules Used

- Route existence, menu visibility, and catalog presence are not counted as complete by themselves.
- OpenAPI/backend availability is not counted as BO completion unless the BO UI calls the API and QA has verified the real menu workflow.
- `complete` requires applicable UI, API connection, form/action workflow, loading/error/empty states, and real menu workflow QA.
- `partial` means some of the workflow exists, but it is not full end-to-end or has not passed real workflow QA.
- `api_gap` means the frozen backend contract does not expose an endpoint required to complete that menu workflow.
- N/A is used only where that CRUD facet is not expected for the seeded menu workflow.

## Current BO Implementation Notes

- Dedicated pages exist for central dashboard, tenant dashboard, tenant maintenance, and tenant support access.
- Most other menus land on `AdminOperationsPage.vue` through the central/tenant catch-all routes.
- `AdminOperationsPage.vue` supports list/detail/report/settings/summary modes, loading/error/empty states, settings JSON save, detail JSON PATCH editor for configured resources, reason-confirm action modals, and JSON payload action modals.
- The current generic page still uses JSON payload modals for creates and updates on many business-critical flows. Those are useful for controlled operations, but they are not equivalent to domain-specific typed forms.
- Prior QA (`20260509-m10-bo-menu-completion-qa-report.md`) verified route/render/API-backed page behavior and some non-destructive write-safety UI, not full destructive CRUD workflows.
